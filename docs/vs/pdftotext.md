# anymd vs pdftotext

[pdftotext](https://poppler.freedesktop.org/) is the plain-text extractor in Poppler's command-line utilities: fast, already installed on many Linux machines, and often the first thing a pipeline uses to feed a PDF to an LLM. anymd is one native Rust binary that returns Markdown with tables, headings and page anchors, reads scans with OCR, reads Office files, EPUB and HTML as well, and is also an MCP server. On the 38 public documents of [AgentDocBench](/guide/benchmarks?entry_surface=seo_vs-pdftotext), anymd scores **96.4** to pdftotext's **42.2**. On the 20 born-digital PDFs, the speed is the same: **0.87 s** for anymd and **0.88 s** for pdftotext, in **200,747** and **201,435** output tokens.

**Where pdftotext shines:** speed. It read the 23 PDFs in 0.90 s, because it runs no OCR. anymd returns 3% more output tokens on those 23 (207,030 against 201,448), and the difference is the text it reads from the three scans. On born-digital PDFs, pdftotext's own output is the reference text that text F1 is scored against, so its text F1 there is 100 by construction; that is why it scores 100.0 on two documents without tables.

### How it was measured

Both tools ran on GitHub-hosted Linux x86_64 runners with 4 CPUs: pdftotext 24.02.0 from the runner's `poppler-utils` as `pdftotext -enc UTF-8 file.pdf -`, in its default reading-order mode without `-layout`, on 2026-09-25, and anymd 8.2.0 on 2026-10-01. Time is the wall time of a fresh process per file, start-up included: the median of three runs after a warm-up for both tools. pdftotext was given only the PDFs, so the 15 other files count as not supported and score 0, as they would for any tool that cannot read them. Newer Poppler releases were not measured. Tokens are counted with `o200k_base`.

The benchmark lives in the anymd repository. The scoring does not know which tool produced an output, and the corpus, ground truth, scoring and raw results are public in [`bench/`](https://github.com/SylphxAI/anymd/tree/main/bench). Anyone can rerun it or [submit a tool](/guide/benchmarks#submit-a-tool).

## Why agent builders switch from pdftotext

### The same speed, with structure

On the 20 born-digital PDFs, anymd took 0.87 s and pdftotext 0.88 s. In that time anymd also finds headings, lists and tables, removes running headers and page numbers, and marks every page with `<!-- page N -->` so an agent can cite it.

### Tables an LLM can read

Plain text flattens a table into a stream of numbers. anymd returns Markdown tables, so table cells F1 is 92.2 against 0.0, financial tables score 95.2 against 74.0, and forms 98.0 against 74.2.

### One tool for every file

pdftotext skipped the 15 Word, PowerPoint, Excel, CSV, EPUB and HTML files in the benchmark and scored 0 on the three scans. anymd converted all 38. Leave out the five categories where pdftotext scores 0, and the overall is still 97.1 for anymd and 72.4 for pdftotext.

### Built for agents

`npx -y @sylphx/anymd setup` adds anymd to Claude Code, Codex, Cursor, VS Code, Claude Desktop, Windsurf and Gemini CLI at once. The MCP tools add what an agent needs for long files: `outline` to jump to a section, `read` with a token budget and a cursor, and `search` across a folder. Files stay on your machine, and `--allow-dir` keeps the MCP server inside one folder.

## When pdftotext is the better fit

- You need only the raw text layer of born-digital PDFs, and pdftotext is already on the machine or in the image.
- Your scripts depend on `-layout` fixed-width text or `-bbox` word coordinates as XHTML.
- You want the PDF's text exactly as Poppler reads it, for example as reference text for an evaluation, as this benchmark does.

## Switch in one line

```bash
pdftotext -enc UTF-8 report.pdf report.txt   # pdftotext
anymd report.pdf -o report.md                # anymd, after npm install -g @sylphx/anymd
```

For MCP, add `npx -y @sylphx/anymd` to your client, or run `npx -y @sylphx/anymd setup` to add it to every client. With Docker:


## FAQ

**Is anymd a drop-in replacement for pdftotext?**
For feeding PDFs to an LLM, yes: `anymd report.pdf -o report.md` replaces `pdftotext report.pdf report.txt` and returns Markdown instead of plain text. Scripts that parse `-layout` or `-bbox` output need changes; anymd's `inspect` returns elements with bounding boxes as JSON.

**Is pdftotext faster than anymd?**
On the 23 PDFs both read, pdftotext took 0.90 seconds and anymd 11.4 seconds, because anymd spent 10.5 seconds reading the three scanned PDFs with OCR, where pdftotext scores 0. On the other 20 PDFs, anymd took 0.87 seconds and pdftotext 0.88 seconds.

**Why does pdftotext score 42.2?**
A document a tool did not convert scores 0. pdftotext reads only PDFs, so the 15 Word, PowerPoint, Excel, CSV, EPUB and HTML files score 0; it has no OCR, so the three scans score 0; and plain text has no tables, so its table cells F1 is 0. On the 23 documents both converted, the overall is 94.8 for anymd and 68.0 for pdftotext.

**Is the benchmark scored against pdftotext?**
In part. For born-digital PDFs, the reference text for text F1 is pdftotext's output, so pdftotext scores 100 on text F1 there. Sentences, reading order and tables are scored against the ground truth in `bench/truth/`, which is checked against the rendered pages.

**Is the benchmark biased toward anymd?**
It lives in the anymd repository, so you can check it: the scoring does not know which tool produced an output, the corpus and ground truth are public, and the documents where pdftotext scores higher are published. Anyone can rerun it or add a tool.

**Is anymd free?**
Yes. anymd is MIT licensed, including the CLI, the MCP server, OCR and transcripts. anymd Pro is an optional one-time purchase, US$29 or the local price in 16 currencies, that adds PDF cite-check and video timelines and frames.
