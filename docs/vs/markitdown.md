# anymd vs MarkItDown

Both tools turn files into Markdown for LLMs, and both are free and MIT licensed. [MarkItDown](https://github.com/microsoft/markitdown) is Microsoft's Python library and CLI. anymd is one native Rust binary that is also an MCP server. On the 38 public documents of [AgentDocBench](/guide/benchmarks?entry_surface=seo_vs-markitdown), anymd scores **96.4** to MarkItDown's **76.8**, converts all 38 in **11.5 s** instead of **75.6 s**, and returns **32% fewer output tokens**.

### How it was measured

Both tools ran on GitHub-hosted Linux x86_64 runners with 4 CPUs: MarkItDown 0.1.8 through its CLI with default options on 2026-09-25, and anymd 8.2.0 on 2026-10-01. Time is the wall time of a fresh process per file, start-up included, median of three runs. A long-running Python process would avoid part of MarkItDown's start-up time; that setup was not measured. Tokens are counted with `o200k_base`.

The benchmark lives in the anymd repository. The scoring does not know which tool produced an output, six of the 38 documents come from MarkItDown's own test files, and the corpus, ground truth, scoring and raw results are public in [`bench/`](https://github.com/SylphxAI/anymd/tree/main/bench). Anyone can rerun it or [submit a tool](/guide/benchmarks#submit-a-tool).

## Why agent builders switch to anymd

### One binary, no Python environment

`npx -y @sylphx/anymd setup` adds anymd to Claude Code, Codex, Cursor, VS Code, Claude Desktop, Windsurf and Gemini CLI at once. Homebrew (`brew install sylphxai/tap/anymd`), winget (`winget install Sylphx.anymd`), Cargo (`cargo install anymd`) and Docker (`ghcr.io/sylphxai/anymd`) install the same binary. There is no virtual environment to keep in sync and no API key.

### Layouts that usually break stay readable

anymd reads PDF glyph positions, so it keeps columns, tables and forms in order. The biggest gaps on AgentDocBench are two-column papers (98.1 vs 47.6), financial tables (95.2 vs 65.9), forms (98.0 vs 74.8) and CJK documents (99.1 vs 79.8). Table cells F1 is 92.2 vs 57.2.

### Fewer tokens, more of the text

Across the 38 documents anymd returns 368,659 tokens to MarkItDown's 538,388, while keeping more sentences verbatim (97.7 vs 73.7). Its MCP tools add what an agent needs for long files: `<!-- page N -->` anchors to cite, `outline` to jump to a section, `read` with a token budget and a cursor, and `search` across a folder.

### Your files stay on your machine

OCR and speech-to-text run locally. anymd goes online only when you pass a URL or explicitly ask it to download a model, and `--allow-dir` keeps the MCP server inside one folder.

## When MarkItDown is the better fit

- You want an in-process Python library today. anymd's Python package is prepared but not yet on PyPI.
- You need ZIP archives, Outlook messages or YouTube URLs, or one of MarkItDown's third-party plugins.
- Your pipeline already uses Azure Document Intelligence or Azure Content Understanding.

## Switch in one line

The CLI has the same shape:

```bash
markitdown report.pdf -o report.md   # MarkItDown
anymd report.pdf -o report.md        # anymd, after npm install -g @sylphx/anymd
```

For MCP, replace the `markitdown-mcp` entry in your client with `npx -y @sylphx/anymd`, or run `npx -y @sylphx/anymd setup` to add it to every client. With Docker:

```bash
docker run --rm -v "$PWD:/data" ghcr.io/sylphxai/anymd report.pdf > report.md
```

More install options are in [Getting started](/guide/getting-started?entry_surface=seo_vs-markitdown).

## FAQ

**Is anymd a drop-in replacement for MarkItDown?**
On the command line, mostly: `anymd report.pdf -o report.md` works like `markitdown report.pdf -o report.md`, and `npx -y @sylphx/anymd setup` adds anymd to your MCP clients. anymd's Python package is not on PyPI yet, so code that imports `markitdown` cannot switch today.

**Is anymd faster than MarkItDown?**
On AgentDocBench, anymd converted all 38 documents in 11.5 seconds and MarkItDown in 75.6 seconds, each timed as a fresh process per file with start-up included.

**Does anymd need Python?**
No. anymd is a native Rust binary. The `npx` install needs Node 18 or newer; Homebrew, winget and Docker install the same binary without Node.

**Can MarkItDown read scanned PDFs?**
Not with its default options: on AgentDocBench its CLI returned no text for three image-only PDFs. It offers an OCR plugin that calls an LLM, and Azure Document Intelligence. anymd reads scans locally with tesseract, or with a local document model after `anymd setup ocr`, and scores 77.9 on the scanned category.

**Is the benchmark biased toward anymd?**
It lives in the anymd repository, so you can check it: the scoring does not know which tool produced an output, the corpus and ground truth are public, six documents come from MarkItDown's own test files, and the categories where anymd loses are published. Anyone can rerun it or add a tool.

**Is anymd free?**
Yes. anymd is MIT licensed, including the CLI, the MCP server, OCR and transcripts. anymd Pro is an optional one-time purchase, US$29 or the local price in 16 currencies, that adds PDF cite-check and video timelines and frames.
