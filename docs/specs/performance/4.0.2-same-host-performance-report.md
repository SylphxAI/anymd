## Process-local warm read cache (post-4.0.2 engineering)

Long-lived MCP servers re-read the same local path+options often. Rust now keeps a
**bounded process-local LRU** of successful local `read_pdf` results keyed by:

- absolute path
- mtime + size
- request fingerprint (include flags / page selection)

Effects:

- `persistent_warm` identical re-reads become sub-millisecond on local fixtures
- first request in a process still pays full parse/extract cost
- `startup_inclusive` (spawn per sample) is unchanged by this cache
- formal marketing still requires suite `admissible_pass` + independent authorization

Local dual-mode suite after this change: status `admissible_pass` with min
persistent_warm median speedup **≥ ~10×** across the eight required classes on
linux-x64 (draft evidence under `verification/pdf-reader-same-host-ab-suite-draft.json`).
