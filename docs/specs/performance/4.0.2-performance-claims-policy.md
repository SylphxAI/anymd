# Sole-Rust 4.0.2 performance claims policy

> Historical: a pdf-reader-mcp release record, kept as written. The `verification/` files it names are no longer in this repository; anymd releases are described in [PUBLISH.md](../../PUBLISH.md).

Status: **formal marketing speedup claims withheld pending harness re-admission**  
Date: 2026-07-24 (post-audit)

## What is accepted now

- 4.0.2 is sole-Rust production with empty production dependency graph.
- Preliminary same-host **startup-inclusive** measurements exist and may be discussed only with full method bounds:
  - linux-x64 same host
  - spawn + initialize + page-1 `include_full_text`
  - not steady-state persistent-server latency
  - not multi-host / OCR-provider guarantees

## Why formal admission was reopened

Independent post-publish audit found:

1. “Warm” samples re-spawned the process each iteration
2. Semantic gate was response-length only
3. Fixture class labels did not run capability-specific tasks
4. Raw per-iteration samples were not durable committed artifacts
5. Suite was not bound to registry-installed exact published natives

## Path back to formal claims

1. Separate `startup_inclusive` and `persistent_warm` modes
2. Stronger semantic outcome comparison
3. Capability-specific tasks (table/structure/search/geometry)
4. Registry-installed exact binaries + host/toolchain/binary digests
5. Durable raw samples under `verification/perf/`
6. Successor independent review with `performanceClaimsAuthorized=true`

## Warm-path note

Persistent warm speedups may include a process-local identical-request cache for
local paths. Claims must say so. First-request and startup-inclusive numbers
remain separate surfaces.
